# ADR-0126: Actions on selected rows come from the action registry, and bulk delete goes one object at a time with the uid as precondition

## Context

The user asked for Lens-style bulk actions: select rows, then delete them, or restart them where that is possible. Sextant already had the parts — row checkboxes and "Select all" in `ResourceTable`, the action registry with `ActionDef.multiple`, Delete with `multiple: true`, and Restart of several objects (ADR-0112) — but the selection's actions were reachable only from the "⋮" or context menu of a row that is part of the selection, which nobody finds. The old Delete dialog also deleted by name only (an object deleted and created again under the same name since the list was shown would be deleted too), could not be stopped, said nothing about objects that come back, and asked for nothing more for 500 objects than for one.

## Decision

- **A selection bar** (`src/features/bulk/SelectionBar.tsx`), rendered by `ResourceTable` between its header and its rows while at least one row is selected: "N selected", the actions, "Clear selection". It is a labelled `role="toolbar"` in the tab order after the header's controls, before the table; the shared `Button` (danger actions as `variant="danger"`), icons of the set. A visually hidden polite live region, kept while the bar comes and goes, says "N selected" when the size changes and "Selection cleared" when it empties (nothing before the first change, as the table's count announcement). "Clear selection" moves the focus to the table's row in the tab order, so it does not fall to the page. The count moved from the header into the bar.
- **The bar's actions are the registry's** (`selection.ts`, `selectionActions`): the ids the table offers (`ResourceDef.actions` or the table's own), only those with `multiple`, judged by the same `appliesTo` as the row menu, in the kind's order with danger actions last. No action is special-cased in the bar; Delete, Restart, Logs, Copy name, Flux and Argo CD actions appear wherever they already applied to a selection.
- **A mixed selection is explained, never silently filtered.** An action that applies to some but not all selected objects is still offered, its button marked "2 of 4" (accessible name "Restart (for 2 of 4 selected)"); its click opens `PartialDialog` first: how many it runs on, which selected objects it leaves out (the first `MAX_LISTED` = 50, then a count) and, where the action says, why — `ActionDef.notApplicableReason` (new, optional). Restart gives the reason from `whyNotRestart` (`restart/model.ts`, the cases `stepOf` refuses: being deleted, a static pod, Sextant's own pod, no controller, a controller Restart does not work through — a Job, any other ReplicaSet owner). "Continue with N objects" runs the action on those N only, through its own confirmation (Restart's dialog, unchanged); Cancel runs nothing. An action applying to none of the selection is not shown. The row menu keeps its old rule (only actions applying to all).
- **The Delete key** on a focused row that is part of the selection opens Delete for the whole selection (the bar's path, so a mixed selection would be explained the same way); on an unselected row, or with a modifier, it does nothing. It clashes with no other key of the table (`rowKeyTarget` uses arrows, Home, End, Page keys; rows use Enter, Space, the menu keys and Ctrl+C); the dock's Delete closes dock tabs only.
- **Delete, for one object or many** (`features/actions/DeleteDialog.tsx`, `deleteRun.ts`, `deleteStore.ts`):
  - The confirmation names the objects (the first 50, then "…and N more"), marks each object with a controller owner reference ("comes back: ReplicaSet web-5d8f") or a Flux / Argo CD manager mark (`hygiene/managed.ts`; "may come back: Argo CD application shop"), and says once, as a whole plural sentence, that deleting such objects replaces rather than removes them; a Namespace in the list adds that everything inside it goes too. Above `TYPE_COUNT_ABOVE` = 20 objects (the Cleanup page's rule, ADR-0081, the same constant) the count must be typed before "Delete" is enabled.
  - One `resource_delete` at a time, in the order shown (the table's), Namespaces last; each request carries `preconditions: { uid }` with the uid of the object the user saw, so an object replaced under the same name since then is kept (the API server answers 409, the outcome says "Kept: … was replaced …"). Without a known uid (a caller with names only) no precondition is sent. resourceVersion is deliberately not a precondition: an object that merely changed (a status update) is still the object the user chose to delete. Each request is sent once (ADR-0055); a refusal does not stop the run.
  - While it runs, Escape, × and the backdrop do nothing; several objects get a progress line ("Deleting demo/a (1 of 3)…", `role="status"`) and "Stop", which lets the request in flight finish and starts nothing more.
  - Every object gets an outcome: deleted, already gone (404), kept because replaced (409 on the precondition), not deleted for lack of permission (403, with the error), not deleted (any other error, with the server's message), not tried (stopped). When every object was deleted the dialog closes, as before; otherwise the result lists each one.
  - The run belongs to the dialog entry (`deleteStore.ts`, as Restart's `runStore.ts`, ADR-0112 amendment): the dialog host unmounts with the main view ("All clusters", no cluster) while the entry stays, so a remount shows the running deletion with Stop instead of offering a second "Delete"; a cluster that disconnects stops the run.
  - One object keeps its look: its own title and text, Cancel and Delete, "Working…", no progress line, no Stop; deleted or already gone closes the dialog. What changed for it is shared: the uid precondition, the controller and GitOps warnings, the namespace warning, and an outcome line instead of the old "0 of 1 deleted" when it fails.
  - Sextant's node-shell pods and debug copies are deleted like any pod, as the single Delete always did: they are the user's own sessions in the window (agents and extensions are refused them by the guard, ADR-0045/0056, unchanged).
- **Agents and extensions get nothing new**: no command was added; the window uses `resource_delete`'s existing optional `preconditions` (`DeletePreconditions`, `crates/sextant-core/src/resources/mutate.rs`, ADR-0081).

## Why

- The bar reads the registry instead of hard-coding Delete and Restart, so a feature's multi-object action (an extension's included) reaches the bar the day it is registered, and the bar and the menu can never disagree on what applies.
- Offering a partial action with an explanation, rather than hiding it, answers "why is Restart missing?" — the usual surprise with a selection of bare and owned pods; running it on the applicable part only after a click on "Continue" keeps the user deciding.
- The uid precondition is the narrowest check that keeps a re-created object (a StatefulSet's pod, a recreated ConfigMap) out of a deletion confirmed for its predecessor, without refusing objects whose status changed in the meantime.
- Closing on full success keeps a routine delete one click; the list appears exactly when something needs reading.

## Consequences

- A table's selection is of one kind, so the bar never mixes kinds; "mixed" means objects of one kind that an action treats differently.
- `selected` is the rows shown: rows filtered out by the search drop out of the selection (as before), so the bar acts only on what is visible.
- A deletion started and then left (window closed) stops where it was; nothing resumes.
- Tests: `src/features/bulk/bulk.test.tsx` (bar shown and hidden with the selection, only actions for all or part of it, danger last, axe on the table with the bar, live region, focus after clearing, a mixed Restart explained and run on its part, Cancel, the Delete key), `src/features/actions/delete.test.tsx` (order with Namespaces last, uid preconditions, Stop, every outcome, the typed count at 20 and 21, owned / namespace warnings with axe, one object, the run surviving a remount), `src/features/restart/model.test.ts` (`whyNotRestart`).
