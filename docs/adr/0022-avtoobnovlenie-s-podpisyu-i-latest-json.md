# ADR-0022: Автообновление через `tauri-plugin-updater`, подпись ключом проекта, `latest.json` в GitHub Releases

## Контекст

После 0.1.0 новые версии ставились только вручную. Установщики не подписаны сертификатами ОС (аккаунтов Apple и Microsoft нет, подпись вынесена в `Later`), а релиз по тегу `v*` собирает `release.yml`.

## Решение

Приложение использует `tauri-plugin-updater` и `tauri-plugin-process` (relaunch). Endpoint — `https://github.com/FriendsOfKubernetes/sextant/releases/latest/download/latest.json`. Обновления подписаны ключом пользователя: публичная часть вписана в `tauri.conf.json`, приватная и пароль лежат в GitHub Secrets `TAURI_SIGNING_PRIVATE_KEY` и `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`. `createUpdaterArtifacts: true`, `release.yml` собирает артефакты и `latest.json` (`includeUpdaterJson`). Проверка идёт при старте (настройка, по умолчанию включена) и по кнопке «Check for updates»; показываются версия и заметки, «Install and restart» ставит обновление. На Linux обновляется AppImage, для `.deb` приложение подсказывает обновить пакетом. Версия приложения видна в Settings, а CI сверяет тег с версией.

## Почему

- Встроенный механизм Tauri, ключ бесплатный, аккаунтов Apple и Microsoft не нужно.
- Ручная переустановка отвергнута: ради её отмены и затеяно обновление для команды.
- Подпись установщиков сертификатами ОС отвергнута как платная и вынесена в `Later`; подпись обновлений её не заменяет, а лишь проверяет, что пакет собран владельцем ключа.

## Последствия

- Потеря приватного ключа или пароля означает, что установленные копии не примут ни одно обновление: придётся ставить вручную. Утечка того же ключа позволит подделать обновление.
- Установщики по-прежнему без подписи ОС, поэтому предупреждения Gatekeeper и SmartScreen остаются.
- Сценарий проверен в Vitest с моком плагина и `actionlint` для `release.yml`. Живая установка обновления, особенно на macOS и Windows, не проверялась.
- `.deb`-пользователи обновляются вручную, пакетом.
- Адрес `latest.json` привязан к имени репозитория и к последнему опубликованному релизу: релиз без артефактов обновления и `latest.json` сломает проверку у всех установленных копий.
- Версия в манифестах должна совпадать с тегом (проверяется в CI): иначе проверка обновления будет сравнивать неверные версии.
