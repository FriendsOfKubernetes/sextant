# ADR-0036: Вид полосы кластеров (с подписями или без) — поле фронтенда в настройках окна

## Контекст

Состояние интерфейса (`useAppStore`) живёт только в памяти; `localStorage` в проекте не используется нигде. Размеры сайдбара и дока, последний кластер сохраняются через `useLayoutPersistence` в `window.*` файла `settings.json`. Backend сам пишет только `kubeconfigSources` и размер окна, поэтому `update_settings` берёт эти поля из сохранённой копии. Развёрнутая полоса должна пережить перезапуск (R13i).

## Решение

`WindowLayout.railExpanded` — булево поле с умолчанием `false` в схеме настроек (Rust и сгенерированный TS-тип). Читает и пишет его только фронтенд: состояние в `useAppStore` (`railExpanded`, `setRailExpanded`), запись — существующий `useLayoutPersistence`. В `update_settings` поле не добавляется. Один флаг на широкую раскладку и на выдвижную панель узкой.

## Почему

- Поле, которое пишет backend, отвергнуто: ничто в backend его не меняет, а лишняя запись в `update_settings` стала бы ещё одним полем, которое нужно помнить при правках.
- `localStorage` отвергнут как отдельное место: в проекте им не пользуются нигде, и вид полосы оказался бы в другом хранилище, чем остальной вид окна. Прямо в материалах этот вариант не разбирался.
- Только в памяти отвергнуто требованием: вид должен сохраняться между запусками.
- Отдельный флаг для узкой раскладки не вводили: спецификация требует, чтобы выдвижная панель показывала полосу «в выбранном виде».

## Последствия

- Поле есть в Rust-схеме (для чтения старых файлов с `serde(default)` и для генерации типов), но управляет им фронтенд: любой, кто будет писать `WindowLayout` из backend, должен его сохранять, иначе вид сбросится.
- Старые `settings.json` читаются: поле добавлено со значением по умолчанию (покрыто тестом).
- Запись идёт с задержкой 300 мс: при закрытии окна сразу после переключения вид может не сохраниться.
- Один вид на все кластеры и на обе раскладки: выбрать «с подписями только в узком окне» нельзя.
