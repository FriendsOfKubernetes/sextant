# ADR-0001: The UI is drawn in Tauri 2

## Context

The user needs a Rust application for Linux, macOS and Windows, possibly with a mobile version later, with a Lens-class interface: tables of thousands of rows, a terminal, a YAML editor, charts.

## Decision

The UI is drawn in Tauri 2: all logic lives in Rust, and the screen is React and TypeScript in the window's system WebView.

## Why

- Electron was rejected. It ships its own Chromium and weighs several times more (an argument from the specification), it has no mobile targets in the same framework, and its usual scheme keeps the logic in Node. Requirement R01 is that all logic is in Rust.
- A pure-Rust UI was not examined separately in the materials. The choice of web libraries "exactly for the Lens areas" indirectly counts against it: a terminal, a YAML editor, a virtualized table. Ready-made equivalents for a Rust GUI would have to be found or written from scratch.
- Tauri 2 gives both desktop and mobile targets in one framework. This is the only argument for "readiness for a mobile version" that does not require a rewrite.

## Consequences

- Every OS has its own system WebView, and page behavior may differ. Linux is checked here, while macOS and Windows are checked only on GitHub Actions, which had never been run at the time of delivery.
- Browser habits do not carry over: `window.open` in a Tauri window does not open the system browser (see ADR-0012).
- End-to-end checking of the window is possible only through `tauri-driver`, that is, with a separate build of the app.
- The framework's mobile targets are promised but were never built. A mobile build is out of scope for this work.
- A boundary between two languages appears. Its cost is described in ADR-0007.
