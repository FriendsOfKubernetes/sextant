# ADR-0001: Интерфейс рисуется в Tauri 2

## Контекст

Пользователю нужно приложение на Rust для Linux, macOS и Windows, возможно с мобильной версией позже, с интерфейсом уровня Lens: таблицы на тысячи строк, терминал, редактор YAML, графики.

## Решение

Интерфейс рисуется в Tauri 2: вся логика живёт в Rust, экран — React и TypeScript в системном WebView окна.

## Почему

- Electron отвергнут. Он несёт собственный Chromium и весит в разы больше (довод из спецификации), мобильных целей в том же каркасе у него нет, а привычная для него схема держит логику в Node. Требование R01 — вся логика на Rust.
- Интерфейс на чистом Rust в материалах отдельно не разбирался. Косвенно против него работает выбор веб-библиотек «ровно под зоны Lens»: терминал, редактор YAML, виртуализированная таблица. Готовых аналогов для Rust-GUI пришлось бы искать или писать самим.
- Tauri 2 даёт и десктоп, и мобильные цели в одном каркасе. Это единственный довод в пользу «готовности к мобильной версии», который не требует переписывания.

## Последствия

- Системный WebView у каждой ОС свой, и поведение страниц может отличаться. Linux проверяется здесь, а macOS и Windows — только на GitHub Actions, который на момент сдачи ни разу не запускался.
- Браузерные привычки не переносятся: `window.open` в окне Tauri системный браузер не открывает (см. ADR-0012).
- Сквозная проверка окна возможна только через `tauri-driver`, то есть с отдельной сборкой приложения.
- Мобильные цели каркаса обещаны, но не собирались. Мобильная сборка вне рамок этой работы.
- Появляется граница между двумя языками. Её цена описана в ADR-0007.
