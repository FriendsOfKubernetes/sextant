# ADR-0133: Resource details use shared disclosures and per-kind section preferences

## Context

Long resource cards have many headings, tables and charts with similar visual weight. Users need to distinguish sections and hide the ones they rarely use across objects of the same kind. Hiding their DOM with CSS alone would leave their watches and metric polls running.

## Decision

- Use the shared details `Block` as a disclosure inside the Overview of a resource card. Primary headings are 0.9375rem and nested headings 0.875rem; preceding gaps are 1rem and 0.625rem, with none before the first block. Constant 1px theme borders separate primary sections; closed rows balance the whitespace above and below the visible header. Expanded groups with nested headings have a 1px gutter guide and ticks in `--color-control-border`. Container branches continue across their tab strip and framed fields to the last subsection heading, including Mounts; the frame keeps its own border. All guides are decorative CSS and ignore pointer events. There is no detection of nearby table borders or DOM measurement for separators or guides.
- The outer gutter begins at the parent heading's center with a tick matching its children's ticks. Sibling segments and a short segment ending at each heading's tick stop it at the last immediate child's heading, including when that child's body is expanded; it never spans that final body's height. Closing the parent removes the branch. Nested container frames remain ordinary frames.
- A container's own branch uses a separate gutter 3 CSS pixels inward from its parent's gutter, independent of text size. It stays outside the frame, keeping the Pod-to-Containers branch separate from the branch connecting Environment, Environment from and Mounts, including when the container tabs wrap. Its color mixes the control-border token with 15% black to distinguish the levels. The table and text positions do not change.
- A native heading button owns `aria-expanded` and `aria-controls`; independent actions stay outside it. Closing removes the body, including expensive child components. Existing source owners are split or gated on the same disclosure when needed. Shared watches and pollers retain their existing release and linger policy and other consumers remain active. Conditional sections can briefly observe a source to establish applicability before a remembered closed header can be retained.
- A closed conditional section releases its applicability source after a completed present, absent or unknown result. Failed, forbidden and capped lists cannot prove absence; a known applicable or unknown header remains available while reopening loads its next snapshot. Sources needed by visible fields or header actions remain independent owners. A small feature-local probe shares this lifecycle without changing the watch stores.
- Preferences use the registry section ID and explicit semantic block IDs, scoped by API group and kind. Object names, namespaces, API versions, translated titles and sibling positions are not preference keys. Repeated instances of a semantic subsection share its preference.
- Appearance offers `global` (the default), `cluster` and `none` memory modes. `appearance.detailsSections` and `clusters[id].detailsSections` keep independent per-kind maps of explicit open/closed booleans; switching modes does not copy one bank over another. The setting label and select use the existing wrapping row with a gap. In `none` mode choices survive tab changes in the same open card and reset when the card is reopened or a different object is selected. YAML starts closed unless an explicit preference opens it, and its editor and masked serialization are deferred until expansion. Disclosure controls and source acquisition wait for the initial settings response, so a late per-cluster or session-only mode cannot write into the global bank.
- Expand all and Collapse all sit above the Overview's scrolling body. Each action replaces only the current kind's map with the reserved `*` default in one queued write, including unmounted or future subsections. Individual choices override this default; another bulk action clears those exceptions. Expand all explicitly opens YAML too. Neither action enumerates the DOM or mounts content merely to discover section IDs. Controls are disabled until settings have loaded.
- Use the existing serialized settings queue and shared cache. Only unsaved edits live in the window store. A write failure remains effective for the session and is reported. The lenient Rust reader bounds each bank to 256 kinds and 256 sections per kind, with keys of at most 240 characters; a frontend edit above the bounds reports a save failure instead of silently claiming persistence. Missing or invalid memory mode reads as `global`, malformed map entries are skipped independently. No IPC command, SDK method or dependency is added.

## Consequences

- Primary separators and guide segments are CSS borders rather than filled 1px strips, matching table rules at fractional Windows display scales. Every segment uses the same border stroke, including the beginning across container tabs and frames. No device-pixel measurement or JavaScript correction is needed.
- Heading colors follow the theme's text token: primary headings mix in 2% white, nested headings 2% black. This small distinction is scoped to disclosure titles; field values, status colors and icons retain their own tokens.
- Explicit non-frame groups and leading flow wrappers connect guides across policy parts and introductory text. Narrow headers put actions on a second grid row; decorative segments follow that row while the starting tick stays at the title's center. Empty policy paragraphs contain their margins rather than breaking the guide. This is structural CSS, not table detection or geometry measurement.
- Collapse state follows the user's choice across resources and restarts without storing another copy per object. Pod and Node preferences remain independent even when both show Metrics.
- Collapsing a body resets its transient component state; reopening reads the current objects and shared sources. A link revealing Requests opens its disclosure and focuses the heading button.
- Blocks outside the details disclosure scope retain their existing static behavior. Extension tabs and summary actions retain their existing layout and lifecycle.
- Coverage includes settings compatibility and bounds, scopes and restart reloads, rapid and failed saves, bulk replacement and individual exceptions, one write per bulk action, unmounted descendants, real subscription release/reacquisition, other shared consumers, nested preferences, keyboard actions and accessibility. Browser geometry is checked separately because Vitest does not apply the stylesheets.
