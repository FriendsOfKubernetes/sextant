# ADR-0030: Вид из discovery читается в предпочтительной версии, если запрошенной версии кластер не обслуживает

## Контекст

CRD Flux и Argo CD в разных кластерах обслуживаются в разных версиях API (история 3: «поддерживаются версии API, которые обслуживает кластер»). Discovery хранит для вида одну версию — предпочтительную (ADR-0015 оставил открытым, какую именно). Реестр видов окна ключует вид по `group/Kind` без версии, а `KindView` для зарегистрированного вида берёт версию из `registered.kind.version`, не дожидаясь discovery. До сборки неизвестный кластеру вид давал `NotFound: the cluster does not serve …`; в `notes.md` одновременно сказано, что при несовпадении версии ядро уже берёт любую обслуживаемую. Было ли это поведение новым, материалы не разводят.

## Решение

`resolve_kind` (`get.rs`): запрошенная версия берётся, если discovery её даёт; иначе используется версия из discovery, и объект приходит с этой `apiVersion`. Встроенные виды не меняются. Вид, обслуживаемый, но не предпочтительный, читается в предпочтительной версии. Виды Flux регистрируются в реестре с предпочтительной версией из discovery. `replace_yaml` и `apply_yaml` идут по URL версии из документа (`resolve_document_kind`, `pub(crate)` в `get.rs`), если группа эту версию обслуживает; иначе `notFound` без запроса. Возврат к версии из discovery действует только для get, watch и patch по `ObjectRef`.

## Почему

- Жёсткая версия из реестра (ошибка `NotFound`, если кластер её не обслуживает) отвергнута: условие истории 3 — работать с версиями, которые обслуживает кластер.
- Discovery по-прежнему хранит одну запись на `(group, kind)` (ADR-0015); вторую версию ядро подбирает при обращении. Хранить все версии в discovery в материалах не обсуждалось.
- Для `apply` и `replace` возврат отвергнут: тело запроса несёт `apiVersion` документа, и при другой версии в URL API-сервер отказывает. Пример: HelmRelease в `v2beta2` при предпочтительной `v2`.

## Последствия

- Фронтенд может получить объект в другой `apiVersion`, чем регистрировал. Колонки и детали (`status.artifact.revision`, `status.lastAppliedRevision`, `status.inventory`) рассчитаны на поля, существующие в этой версии; совпадение полей между версиями в материалах не сверялось.
- Патчи действий пишут аннотацию и `spec.suspend` в объект предпочтительной версии; одинаково ли эти поля выглядят в старых версиях, не проверялось.
- Документ в версии, которую группа не обслуживает, отвергается сразу, до запроса к серверу: ошибка `notFound` видна без сетевого вызова.
- Реестр не различает версий (ключ `group/Kind`): две версии одного вида в нём не зарегистрировать.
