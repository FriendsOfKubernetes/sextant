# ADR-0037: Requests и limits пода считаются на фронтенде из spec, init-контейнеры не суммируются

## Контекст

Метрики дают только потребление (metrics-server или Prometheus). Requests и limits уже лежат в `spec.containers[].resources` пода, который окно получает подпиской, но показывались только чипами по каждому контейнеру и нигде не суммировались. Разбор количеств есть и в TS (`parseQuantity`), и в ядре (`quantity.rs`). Нужно показать request и limit пода рядом с потреблением, в том числе без метрик (истории 16–19).

## Решение

Считаем на фронтенде из объекта пода, только по `spec.containers`. Request пода — сумма заданных; если задан не у всех контейнеров, добавляется «set on N of M containers». Limit пода показывается, только когда он задан у каждого контейнера; иначе «no limit». Init-контейнеры не складываются. Полоска потребления идёт от limit, если он полный, иначе от request, если он полный. Ничего не задано — строка не показывается. Requests и limits видны и при недоступных метриках.

## Почему

- Расчёт в ядре (Rust) отвергнут: данные уже есть в объекте пода в окне, а вычисление потребовало бы новой команды и нового типа через границу (ts-rs, три места регистрации). Прямо в материалах причина названа как «считаются на фронтенде», остальное — вывод.
- Суммировать init-контейнеры отвергнуто: в момент работы пода они не идут (спецификация).
- Частичный limit как сумма заданных отвергнут: пользователь прочёл бы сумму как предел пода, хотя один контейнер может не иметь предела; поэтому «no limit».
- Брать значения только из метрик отвергнуто: при недоступном metrics-server или Prometheus requests и limits пропали бы.

## Последствия

- Число расходится с тем, что учитывает планировщик, если init-контейнер просит больше суммы обычных, и не учитывает sidecar-контейнеры в `initContainers`. Это следствие правила «только `spec.containers`», проверено только по тексту спецификации.
- Два места разбора количеств (TS и Rust) нужно держать согласованными вручную.
- Показ «set on N of M» и «no limit» делает блок многословнее у подов без явных значений.
- Значения берутся из spec на момент получения объекта; то, что подставил admission (LimitRange), уже в spec, а не вычисляется отдельно.
- Узлы и Deployment не затронуты: расчёт сделан только для Pod (вне рамок).
