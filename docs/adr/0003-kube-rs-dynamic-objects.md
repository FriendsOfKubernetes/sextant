# ADR-0003: Kubernetes-клиент — kube-rs, ресурсы как динамические объекты, TLS на rustls

## Контекст

Нужны встроенные виды и произвольные CRD в одном интерфейсе; сборка идёт под три ОС, включая кросс-сборку на GitHub Actions.

## Решение

Клиент — `kube-rs` с `k8s-openapi`. Все ресурсы обрабатываются как `DynamicObject` через discovery, одним путём для встроенных видов и CRD. TLS — `rustls`, без OpenSSL.

## Почему

- Типизированные структуры на каждый вид отвергнуты: CRD в них не покрыть, пришлось бы вести два пути (типизированный и динамический) для одной таблицы и одних деталей.
- OpenSSL отвергнут: `rustls` проще для кросс-сборки под три ОС.
- Самописный клиент не рассматривался: `kube-rs` назван в спецификации стандартным клиентом Kubernetes в Rust.

## Последствия

- Компилятор не проверяет поля объектов. Во фронтенд уходит сырой JSON, а колонки и детали по видам описаны в реестре на стороне интерфейса.
- Discovery берёт только предпочтительную версию группы, а упавшая группа пропускается. Объекты в непредпочтительных версиях и целиком недоступная группа молча не видны.
- Exec-плагины работают так, как их поддерживает `kube-rs`. Для облачных кластеров это не проверяется (вне рамок).
- Отказ сертификата приходит кодом `unreachable`. Интерфейс отличает его от «сервер недоступен» только по тексту сообщения, что хрупко (ADR-0008).
- Все ошибки `kube` обязаны идти через единственную функцию преобразования, иначе утекут секреты exec-плагина.
