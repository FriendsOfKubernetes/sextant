# ADR-0019: Временный kubeconfig терминала удаляется синхронно, остатки чистятся при старте

## Контекст

Временный kubeconfig жил как `TempPath` внутри задачи `forward_term` и пропадал, когда задача завершалась; остановка сессий делала только `AbortHandle::abort()`, который асинхронный. `close_all` вызывался лишь на `WindowEvent::Destroyed`, так что Cmd+Q на macOS и перезагрузка окна его не вызывали, а после падения файл оставался навсегда.

## Решение

Guard временных файлов сессии (`kubeconfig` и файлы запуска оболочки) хранится в `TermSession`; `Sessions::stop`, `stop_cluster` и `stop_all` сбрасывают его синхронно, к возврату из вызова файл удалён. `RunEvent::Exit` и `ExitRequested` вызывают `AppState::close_all`. При загрузке страницы окно вызывает `streams_reset` (ADR-0013), и старые сессии закрываются. При старте приложения `remove_stale_temp_kubeconfigs` удаляет оставшиеся файлы `sextant-kubeconfig-*` в системном temp-каталоге, принадлежащие текущему пользователю.

Заменяет ADR-0010 в части «файл должен исчезнуть после сессии, но при аварийном завершении может остаться».

## Почему

- Guard в задаче с `abort()` отвергнут: прерывание не ждёт ничего, а если оболочка вышла раньше первого resize или input, цикл ещё и сам держал guard. Файл с учётными данными кластера оставался на диске.
- Одной очистки при старте мало: между выходом и следующим запуском файл с сертификатами и токенами лежал бы на диске.
- Одного синхронного удаления тоже мало: при падении процесса или `SIGKILL` оно не сработает, поэтому добавлена очистка при старте.

## Последствия

- Падение и убийство процесса по-прежнему оставляют файл (права 0600, на Windows они действуют иначе) до следующего запуска.
- Очистка при старте идёт по префиксу и владельцу; защищает ли она файлы второй живой копии Sextant того же пользователя, в материалах не описано.
- Каталоги `sextant-shell-*` (обёртки оболочек, ADR-0018) при старте не чистятся: очистка удаляет только файлы.
- Старт, переживший `streams_reset`, должен сам убрать свой guard: этим занят `AppState::undo_if_reset`.
- Помимо терминала, тот же префикс получают временные kubeconfig для `helm`; как стартовая очистка относится к ним, в материалах не описано.
