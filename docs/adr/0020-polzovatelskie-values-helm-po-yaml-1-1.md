# ADR-0020: Установка чарта сохраняет только изменённые values, сравнение по правилам YAML 1.1

## Контекст

Установка чарта через `helm` (ADR-0005) сохраняла как пользовательские весь файл default values, который пользователь видел в редакторе. Ядро для YAML использует `serde_yaml` (правила YAML 1.2), а `helm` читает values как YAML 1.1 (go-yaml v2).

## Решение

`cli::install_chart` перед установкой выполняет `helm show values` и передаёт `helm` только то, что `cli::changed_values(defaults, edited)` нашла изменённым: без правок у нового релиза пустые user values, при изменении одного ключа — только он. `changed_values` и `values_to_yaml` следуют YAML 1.1 по go-yaml v2, сверено с helm v4.3: типизация plain-скаляров, merge-ключи `<<` (при повторе побеждает более поздний ключ документа, в списке карт — более ранняя карта), экранирование U+2028, U+2029 и U+0085. `changed_values` выдаёт результат flow-стилем.

## Почему

- Сохранять весь файл (прежнее поведение) отвергнуто: user values закрепляют старые defaults, и при обновлении чарта его новые значения по умолчанию перестают действовать.
- Сравнение по YAML 1.2 отвергнуто: один и тот же текст `helm` и `serde_yaml` типизируют по-разному (`yes`, `on` — булевы у YAML 1.1, строки у 1.2; merge-ключи тоже), и разница в разборе давала бы неверный вывод «изменилось / не изменилось».

## Последствия

- Каждая установка делает лишний вызов `helm show values`: нужны доступный репозиторий и время.
- Правила YAML 1.1 сверены с одной версией `helm`; расхождение с другими версиями в материалах не проверялось.
- Правила разбора YAML 1.1 ядро воспроизводит само, поэтому расхождение с `helm` в краевом случае ловится только сверкой с настоящим `helm`.
- В сохранённом релизе user values выглядят как flow-YAML (`{a: {b: 1}}`), а не как привычный блочный файл.
- Сюда же относится `values_to_yaml`: любой другой код, превращающий значения в YAML для `helm`, должен идти через него.
