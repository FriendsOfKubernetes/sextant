# ADR-0018: Терминал возвращает KUBECONFIG после пользовательских rc через обёртки оболочек

## Контекст

Терминал получал `KUBECONFIG` временного файла в окружении, но оболочка стартовала как login-shell и читала `~/.zshrc` или `~/.bashrc`; `export KUBECONFIG` оттуда перебивал выбранный кластер. Оболочка наследовала всё окружение приложения, включая `HELM_*`, `KUBECONFIG` и переменные упаковки AppImage.

## Решение

Приложение запускает оболочку так, чтобы `KUBECONFIG` восстанавливался уже после пользовательской инициализации. bash — `bash --posix -i` с `ENV=<временный rc>`: rc снимает `ENV`, выходит из POSIX-режима, выключает `inherit_errexit`, подключает `/etc/profile` и ставит `HISTFILE=~/.bash_history`, если он не задан. zsh — во временном каталоге лежит только `.zshenv`, возвращающий пользовательский `ZDOTDIR`, а `KUBECONFIG` восстанавливает одноразовый хук `precmd`. fish — `--init-command`, путь передаётся через `SEXTANT_KUBECONFIG`, который init-команда снимает. Остальные оболочки и PowerShell — видимая пометка во вкладке: приватная OSC 7719 в потоке вывода (`TerminalViewProps.kubeconfigNotice`). Из окружения оболочки удаляются `HELM_KUBE*`, `HELM_NAMESPACE`, `HELM_DRIVER`, `KUBECONFIG` приложения и переменные AppImage.

Заменяет ADR-0010 в части «оболочка запускается как login-shell, и профиль может переопределить `KUBECONFIG`».

## Почему

- Оставить как было отвергнуто: молчаливый `kubectl` на чужой кластер хуже любой ошибки, а `export KUBECONFIG` в рабочих rc — обычное дело.
- Править пользовательские rc-файлы отвергнуто принципом ADR-0010: пользовательские файлы приложение не меняет.
- Первый вариант для bash, `--rcfile <tmp> -i`, заменён на `--posix` с `ENV`: у него в материалах названы недостатки — не работали `logout` и `~/.bash_logout`. Прямо записанной причины замены нет.
- Для оболочек без надёжного приёма принята честная пометка вместо обещания: без неё пользователь считал бы, что гарантия есть.

## Последствия

- Для каждой оболочки свой механизм, и их три плюс пометка. Для `sh`, `dash`, `nu` и PowerShell гарантии нет, только предупреждение во вкладке.
- Обёртка bash вручную воспроизводит порядок инициализации (`/etc/profile`, `HISTFILE`, `inherit_errexit` — следы «ремонтов»), и расхождения с поведением обычного login-shell возможны. Работают ли теперь `logout` и `~/.bash_logout`, в материалах не перепроверялось.
- Восстановление в zsh одноразовое: если пользователь потом сам поменяет `KUBECONFIG` в сессии, хук не вернёт его обратно.
- Тест на `export KUBECONFIG=/other` идёт для bash и zsh, если они есть в системе. macOS и Windows живьём не проверялись.
- Временные каталоги `sextant-shell-*` после падения не чистятся при старте (ADR-0019).
