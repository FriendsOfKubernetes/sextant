# ADR-0024: Flux и Argo CD читаются и управляются только через Kubernetes API, без их CLI

## Контекст

В кластерах пользователя и команды работают Flux и Argo CD. Нужно видеть состояние их объектов и выполнять действия: reconcile, suspend/resume, sync, refresh, terminate. У обоих инструментов есть собственные CLI (`flux`, `argocd`). Для Helm выбрана другая схема: чтение нативное, изменения делает установленный `helm` (ADR-0005).

## Решение

Объекты Flux и Argo CD читаются как обычные Custom Resources, действия выполняются патчами тех же объектов через общую команду (ADR-0025): аннотация `reconcile.fluxcd.io/requestedAt`, `spec.suspend`, поле `operation` у Application, аннотация `argocd.argoproj.io/refresh`, фаза `Terminating` у операции. Бинари `flux` и `argocd` не вызываются и на машине не нужны. Единственное место, где Sextant говорит с самим Argo CD, — вход и дифф «желаемое ↔ живое» через его HTTP API (ADR-0027, ADR-0028). Всё остальное, включая действия Argo CD, идёт через Kubernetes API.

## Почему

- Так записано в спецификации: работает с правами пользователя, на машине ничего не нужно.
- Вызов CLI отвергнут по этой же причине: нужен был бы бинарь в PATH и его собственные настройки доступа к кластеру. Для Helm аналогичная зависимость принята (ADR-0005), потому что шаблонизатор нельзя переписать; у Flux и Argo CD действия сводятся к записи полей в объект, и причины звать CLI нет.
- Почему дифф всё же идёт через API Argo CD, а не через Kubernetes API, в материалах прямо не сказано; есть лишь, что данные берёт запрос managed-resources (`targetState` / `liveState`).

## Последствия

- Все действия требуют прав пользователя на патч этих объектов. Проверки прав заранее нет: отказ приходит ошибкой Kubernetes.
- Действие — запрос к контроллеру: Sextant записывает намерение (аннотацию, `operation`), выполняет его контроллер в кластере. Если контроллера нет или он не работает, объект изменится, а действия не будет.
- «Reconcile with source» для Kustomization и HelmRelease — последовательность патчей (сначала источник, потом объект), а не одно атомарное действие.
- Проверено на kind с Flux v2.9.6 и Argo CD v3.5.5. Другие версии в материалах не проверялись. На кластере пользователя (только чтение) действия не запускались; Argo CD там нет.
- Формат патчей (структура `operation`, имена аннотаций) знает фронтенд (`src/features/argocd`, `src/features/flux`), а не ядро. Смена формата у Argo CD или Flux правит фронтенд.
