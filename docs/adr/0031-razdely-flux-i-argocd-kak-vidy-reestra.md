# ADR-0031: Разделы Flux и Argo CD — виды реестра в новых секциях; установка определяется по CRD в discovery

## Контекст

Раздел «Flux» должен появляться, только если в кластере есть Flux, раздел «Argo CD» — только если есть Argo CD (история 1). Устройство сайдбара: страницы (`registerPage`) показываются всегда, без сверки с discovery, а виды, зарегистрированные в реестре, скрываются, если их нет в discovery. `ResourceDef.sidebar` принимает только секции из закрытого union `SidebarSection`. Объекты Flux и Argo CD без регистрации показывались как безымянные Custom Resources со стандартными колонками.

## Решение

`SidebarSection` получает `"flux"` и `"argocd"` (перед `customResourceKinds`). Все виды обоих инструментов регистрируются через `registerResource` с `sidebar` в этих секциях; вида нет в discovery — его нет и в разделе; раздел без видов не рисуется. До прихода discovery разделы скрыты (`DISCOVERED_SECTIONS`; для остальных видов до прихода discovery показываются все). Установленным считается инструмент, у которого в discovery найдены его CRD: Flux — хотя бы одна группа `*.toolkit.fluxcd.io`, Argo CD — `argoproj.io` Application. Раздел Flux — один плоский упорядоченный список. Страницы в этих секциях не регистрируются без собственной проверки (`useClusterKinds` + `findKind`). `ActionId` получает десять значений (`reconcile`, `reconcileWithSource`, `fluxSuspend`, `fluxResume`, `argoSync`, `argoRefresh`, `argoHardRefresh`, `argoTerminate`, `argoDiff`, `argoOpenUi`).

## Почему

- `registerPage` отвергнут как основной путь: страницы показываются всегда, и пришлось бы писать собственную проверку discovery на каждую. Прямо в материалах причина не названа, но следует из устройства сайдбара.
- Определять установку по контроллерам (Deployment, неймспейс) вместо CRD в материалах не обсуждалось; выбор CRD записан в истории 1 без обоснования.
- `suspend` в `ActionId` уже занят действием CronJob, поэтому Flux получает `fluxSuspend` и `fluxResume`.

## Последствия

- Зарегистрированный вид с `sidebar` исчезает из дерева Custom Resources; с `sidebar: null` — не появляется нигде. У зарегистрированного вида берутся только колонки из `def.columns`, printer-колонки CRD не подставляются.
- CRD без контроллера (остался после удаления инструмента) тоже включит раздел: признак — наличие CRD, а не работающая установка. Следует из способа определения, не из проверки.
- Новое действие требует нового варианта закрытого `ActionId` и правки реестра (это правка общей зоны таска 01).
- Установка Flux или Argo CD при открытом подключении показывает раздел без переподключения благодаря ADR-0026.
- Страницы в разделах `flux` и `argocd` без своей проверки показывались бы всегда, даже без инструмента.
