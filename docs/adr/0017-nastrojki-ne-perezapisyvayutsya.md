# ADR-0017: Нечитаемые настройки не перезаписываются, источник kubeconfig с ошибкой виден

## Контекст

Если `settings.json` не читался, `SettingsStore::open` брал умолчания без единого слова; если не разбирался — переименовывал его в `.bak` (затирая прежний `.bak`). Следующее сохранение закрепляло потерю: умолчания обнуляют добавленные источники kubeconfig, настройки кластеров, окно и `helm_path`. Битый файл из `KUBECONFIG` пропускался молча.

## Решение

Нечитаемый файл настроек не уничтожается молча. Файл, который не прочитался или не разобрался, копируется в `settings.json.bak-YYYYMMDD-HHMMSS` (UTC; при совпадении имени `-2`, `-3`, старые копии не затираются), после чего приложение стартует с умолчаниями. При отказе в доступе запись отключена, изменения живут до конца сессии. Команда `settings_status() -> { writable, backupPath, error }` отдаёт состояние, окно показывает баннер с путём (портал из `SettingsButton`, слота на всё окно нет). Источник kubeconfig, который не читается, остаётся в `sources()` с `KubeconfigSource.error`, виден в рейле и в Settings рядом с источником; остальные кластеры работают.

## Почему

- Прежний порядок (одна `.bak`, молчаливые умолчания) отвергнут: вторая порча стирала последнюю хорошую копию, а пользователь не узнавал, что его источники и настройки пропали.
- При отказе в доступе копию сделать нельзя, а запись умолчаний поверх нечитаемого файла была бы той же потерей — поэтому запись отключается.
- Показывать ошибку источника только на экране «нет кластеров» (как было) отвергнуто: при частичном успехе пользователь не узнаёт, что часть кластеров из-за битого файла не появилась.

## Последствия

- В режиме «только на сессию» ничего из изменённого (добавленные источники, цвета, пути) не переживёт закрытие окна. Баннер это сообщает, но сам режим неприятен.
- Копии `.bak-*` накапливаются, и очищать их некому.
- Баннер живёт в `SettingsButton`, поэтому виден там, где отрисована эта кнопка; общего слота для сообщений уровня окна пока нет.
- `KubeconfigSource.error` стал обязательным полем IPC, а `KubeconfigRegistry::sources()` теперь перечитывает файлы при каждом вызове.
- Кластеры из источника с ошибкой в списке не появляются, пока файл не починят; само сообщение показывает причину.
- Перенос настроек Windows после смены `ClusterId` в 0.1.0 этим решением не закрыт: он отдельно вынесен за рамки сборки.
