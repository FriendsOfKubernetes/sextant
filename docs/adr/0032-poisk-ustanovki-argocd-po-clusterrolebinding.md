# ADR-0032: Установка Argo CD находится по ClusterRoleBinding, неоднозначность — ошибка

## Контекст

Sextant подставляет в вход в Argo CD пароль или токен из секретов (ADR-0028) и отправляет их на `argocd-server` через проброс (ADR-0027), где проверка TLS отключена. Сначала неймспейс установки искали по сервису: метка `app.kubernetes.io/name=argocd-server`, иначе `argocd`. Ревью ветки показало дыру: в кластере с арендаторами любой, кто может создать объекты в своём неймспейсе, мог подложить Service с такой меткой, `argocd-cm` или Secret с токеном, и Sextant отправил бы настоящий пароль в чужой неймспейс.

## Решение

Признак установки — ClusterRoleBinding `argocd-application-controller` или `argocd-server` (и `<release>-…` для установки из Helm). Сверяются имя привязки и имя ServiceAccount; неймспейс берётся у ServiceAccount и сужается до неймспейсов, где есть `argocd-cm`. Если признака нет (namespaced-установка или нет прав на ClusterRoleBinding), кандидаты ищутся по `argocd-cm` и `argocd-initial-admin-secret`: берётся единственный кандидат либо `argocd`; иначе `notFound` с префиксом `argocd::AMBIGUOUS_INSTALLATION` и перечнем неймспейсов. Фронтенд (`isAmbiguousInstallation`, `ambiguousInstallationText`) при такой ошибке ничего не открывает и не подставляет. Сервис `argocd-server` ищется только в найденном неймспейсе — и ядром (`find_server`), и кнопкой «Open Argo CD UI»: `argocdNamespace` теперь равен `api.argocd.status().namespace`.

## Почему

- Поиск сервиса по метке во всех неймспейсах отвергнут: арендатор мог подложить Service, `argocd-cm` или токен и перехватить пароль.
- Первый по алфавиту из найденных отвергнут: то же самое, подкладывающему достаточно выбрать имя неймспейса.
- Привязка кластерной роли взята как признак, который арендатору, как правило, нельзя создать без кластерных прав. Это очевидное следствие, в материалах оно прямо не проверялось.
- При неоднозначности ошибка, а не угадывание: неверный выбор отправил бы пароль не туда, а ошибка стоит лишь повторного действия пользователя.

## Последствия

- Для основного пути нужно право читать ClusterRoleBinding. Без него (и в namespaced-установке) остаётся запасной путь по `argocd-cm` и `argocd-initial-admin-secret`, который защищён слабее: такие объекты арендатор создать может. Защита там держится на правиле «единственный кандидат либо `argocd`, иначе ошибка». Нужно ли `argocd` быть среди нескольких кандидатов, в материалах не уточнено.
- При нескольких установках Argo CD и отсутствии признака пользователь получает ошибку с перечнем и не может выбрать неймспейс из интерфейса: выбора нет. Ручной выбор в материалах не описан.
- Установка Helm с другим именем релиза определяется только по форме `<release>-…`; нестандартные имена привязок найдены не будут.
- Неймспейс, найденный ядром, определяет всё: источники входа (ADR-0028), ключ в keyring (ADR-0029) и проброс (ADR-0027). Смена признака потребует чистки сохранённых входов только если неймспейс окажется другим.
- Прежнее правило «сервис по метке, иначе `argocd`» (`ARGOCD_SERVER_SELECTOR`, `DEFAULT_ARGOCD_NAMESPACE`) теперь действует внутри уже найденного неймспейса, а не для выбора неймспейса.
