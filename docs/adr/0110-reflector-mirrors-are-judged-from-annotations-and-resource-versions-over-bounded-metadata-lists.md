# ADR-0110: Reflector mirrors are judged from annotations and resourceVersions over bounded metadata lists

## Context

#241 asked for emberstack Reflector: on a Secret or ConfigMap that is a source, where it is allowed and automatically mirrored to; on a mirror, its source and whether it is still in step (in sync / stale / source missing), with stale mirrors and missing sources as problems — without ever reading a Secret's values. Unlike the other projects of this wave Reflector defines **no kind**: everything is in annotations under `reflector.v1.k8s.emberstack.com/` on ordinary Secrets and ConfigMaps (`reflection-allowed`, `reflection-allowed-namespaces`, `reflection-allowed-namespaces-selector`, `reflection-auto-enabled`, `reflection-auto-namespaces`, `reflection-auto-namespaces-selector` on a source; `reflects`, `auto-reflects`, `reflected-version`, `reflected-at` on a mirror; `Mirroring/Core/Annotations.cs`). Reflector writes no status either: a mirror it skips is a line in its log.

## Decision

- **Read-only, frontend only** (`src/features/reflector/`) — except the pattern matching, which the review moved to the core (see the amendment below). Nothing is written to the cluster. There is no sidebar section (no kind to discover); Reflector shows up as a "Reflection" column on the Secret and ConfigMap tables (`extendColumns`), a "Reflection" details section drawn only for objects that carry its annotations, and the problems category `reflector`.
- **The annotations are read as Reflector reads them** (`MirroringPropertiesExtensions.cs`, ES.FX `NamespacedName.TryParse`, `TryGetAnnotationValue`): flags are .NET booleans ("true" in any case, trimmed); `reflects` is `namespace/name` or a bare name (empty namespace, a source Reflector never finds); `reflected-at` loses its quotes.
- **A mirror's state** (`judge.ts`): *source missing* where the source's namespace is read in full and it is not there; *not allowed* where the source no longer permits the mirror's namespace (`CanBeReflectedToNamespace`, for an automatic mirror `CanBeAutoReflectedToNamespace`) — Reflector stops updating a manual mirror and deletes an automatic one; else *in sync* when `reflected-version` equals the source's resourceVersion (Reflector's own check in `ResourceMirror.cs`), *stale* when not; *cannot tell* when the source cannot be read. Values are never read or compared: no hash is needed, since Reflector's own annotation records the version it copied (ADR-0090's hashing in the core stays for Compare).
- **Namespace matching follows Reflector** (`patterns.ts`): a list split on every comma, each pattern a regular expression whose first match (`Regex.Match`) must cover the whole name; an empty list allows every namespace; a label selector parsed as `TryParseLabelSelector` does (unparsable: matches nothing, as Reflector fails closed), ORed with the list; labels from the namespace filter's own Namespace list (one stream for both). The patterns are matched in the core, never in the window (amended below); a pattern that cannot be matched as .NET would is **"cannot tell"**, never a match or a mismatch.
- **Bounded watches** (`store.ts`): metadata-only lists (names, annotations, resourceVersions; the core strips Secrets as always) of the namespaces in view — a mirror's details and table cell ask for its source's namespace, a source's details for its own and the namespaces it may be mirrored to — at most 40 per kind (first asked, first kept; the rest are said to be "not checked"), shared through the resource map's watches and released when nobody asks. Requests are gathered for 50 ms so a table's rows open one list. **No cluster-wide Secret list** except for the opt-in problems.
- **Problems: an opt-in category `reflector`** (`OPT_IN_CATEGORIES`, a toggle on the Problems page, a source of its own in `sourceKey`), since finding every mirror needs a cluster-wide metadata list of every Secret and ConfigMap (each capped at 10 000 objects, the source then truncated) — consistent with ADR-0100's and ADR-0108's amendments. A mirror whose source is missing counts after 2 minutes (a source applied after its mirror), a stale mirror after 10 minutes (Reflector copies within seconds when it runs), an out-of-date mirror the source no longer allows after 10 minutes. "Cannot tell" is never a problem. Agents get none of it (`NEVER_FOR_AGENTS`).

## Why

- Comparing values (or their hashes) to decide "in sync" was rejected: `reflected-version` is what Reflector itself compares, it needs no value, and a value comparison would say "in sync" for a mirror Reflector no longer follows.
- Listing every Secret of the cluster for the details or the column was rejected; a source's mirrors are looked for only where the source allows them, so a mirror left in a namespace the source no longer allows is found only by the opt-in problems (which list everything) or from the mirror's own details.
- Running every pattern as written was rejected: one pathological pattern on a cluster object could freeze the window.

## Consequences

- A source allowed in more than 40 namespaces has its mirrors checked in the first 40 only; the details name the rest.
- A .NET-only pattern leaves the namespaces it names "cannot tell"; the details say which pattern and why.
- Until the core has answered, a source's targets and a mirror's permission are "cannot tell" for a moment; a source's details list no other namespace until then.
- On a cluster without Reflector the column stays empty (it can be hidden like any column).

## Amended (v0.21.0 review): patterns are matched in the core in linear time

The review found that a regular expression from a cluster object could still freeze the window: JavaScript's backtracking `RegExp` took 7.6 s for `(a|a)*b` on 26 characters, and the guard against "a repeated group that itself repeats" missed it (also `((a)+)+b`, `.*.*.*.*.*.*.*.*.*x`). So no pattern is run in the window any more:

- **Core** (`crates/sextant-core/src/reflector.rs`, `match_patterns`): the `regex` crate, whose matching is linear in the pattern and the name, with `size_limit` / `dfa_size_limit` of 1 MiB; at most 64 patterns and 2000 names per call, names up to 253 bytes, patterns up to 256 characters (longer, or compiled too large: `notEvaluated`). Its leftmost-first semantics are .NET's, so `find` is the match `Regex.Match` returns, and a name matches when that first match is the whole name. Syntax the crate refuses (backreferences, lookaround, atomic groups, `\Z`, `\G`, `(?n)`, comments, `\p{IsGreek}`) is `invalid`; so is syntax both accept with different meanings, refused before compiling (`dotnet_divergence`): `[` inside a class, `&&`/`--`/`~~` in a class, `\x{…}`, `\u{…}`, `\U`, `\<`, `\>`, `\b{…}`, `\p` without braces or naming no general category, digit escapes, a `{` that is not a .NET quantifier, a quantifier on a quantifier, the flags `x`/`U`/`u`/`R`, `(?P<…>`. Both read `\A`, `\z`, `\p{Ll}`, `(?i)`, named groups and lazy quantifiers alike, and they run.
- **Command** `reflector_match_patterns(patterns, names)` → one `PatternMatches` (`issue`, `matches`: yes / no / cannotTell) per pattern, run off the async runtime. Pure and window only: a test keeps it out of the MCP tools and the extension methods.
- **Window** (`matcher.ts`): lookups stay synchronous over a cache; a pair not answered yet is "cannot tell" and is queued, the queue goes out batched (≤ 64 × 2000 per call), and the answers rebuild the store's state so every holder judges again. A failed call leaves its pairs "cannot tell" and is asked again after 30 s, never in a loop.
- **An annotation that names no pattern** (",", " ") matches no namespace, as `PatternListMatch` does after `string.IsNullOrEmpty` (the lists are no longer trimmed before that test); only an empty annotation means every namespace.

Rejected: a timeout around `RegExp` (a running regular expression cannot be interrupted in the window's thread), a worker with a time limit (the answer would depend on the machine's speed, and a killed worker still froze one core), and a stricter guard (no syntactic rule catches every backtracking case).
