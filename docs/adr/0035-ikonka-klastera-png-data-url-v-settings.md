# ADR-0035: Иконка кластера — PNG 96×96 в виде data URL в settings.json

## Контекст

Сгенерированные квадратики с инициалами в полосе кластеров не различаются, пользователь хочет свою картинку или цвет с 1–2 символами (брифинг «ок»). Единого хранилища файлов в приложении нет: в каталоге данных лежат только вставленные kubeconfig. Диалог выбора файла возвращает путь, команды чтения файла нет. CSP пропускает `data:` и `blob:`, но не `file://` и не asset-протокол. Поля `clusters[id]` в `settings.json` принадлежат фронтенду.

## Решение

`ClusterSettings.icon` хранит либо текст (до 2 графем), либо картинку как `data:image/png;base64,…`. Файл PNG, JPEG, SVG или WebP до 5 МБ выбирается элементом `<input type="file">` внутри диалога и читается `FileReader`, рисуется на canvas с вписыванием по пропорциям в 96×96 с прозрачным фоном и сохраняется как PNG. Новых команд backend и доступа к файловой системе нет. Рисуется только `dataUrl` с префиксом `data:image/png;base64,`; остальное игнорируется.

## Почему

- Копирование выбранного файла в каталог приложения отвергнуто: нужна новая команда Rust в трёх местах (`generate_handler!`, `commands.ts`, тесты команд), своё хранилище, чистка при удалении кластера и расхождение с `settings.json` при переносе. Спецификация: проще и безопаснее.
- Хранить путь к файлу отвергнуто: картинка не загрузится ни через `file://`, ни через asset-протокол из-за CSP; читать файл по пути нечем без новой команды. Что файл на диске может пропасть или быть заменён, в материалах не сказано — это мой вывод.
- Хранить исходный файл целиком отвергнуто: размер записи тогда ничем не ограничен; нормализация в 96×96 ограничивает её.
- Показывать произвольный `data:` отвергнуто: рисуется только PNG из нормализатора.

## Последствия

- Каждая иконка лежит в `settings.json`, который целиком читается и пишется при любом изменении настроек; по мере появления иконок файл растёт. Размер записи ограничен 96×96, но не нулевой.
- Оригинал теряется: SVG растеризуется, и сменить размер без повторного выбора файла нельзя.
- Иконка переезжает вместе с `settings.json`, но не привязана к kubeconfig и не переживёт сброс настроек (нечитаемый файл — копия `.bak-…` и умолчания).
- Выбор файла и canvas работают в WebView; в тестах это скрыто за `readIconImage` и ошибками `type`, `size`, `read`. Проверку на Windows и macOS даёт только CI.
- Поле принадлежит фронтенду и не входит в `update_settings`: мок `settings_update` не эмулирует сохранение полей backend, поэтому тест не поймает потерю иконки, если поле когда-нибудь окажется backend-owned.
- Сброс убирает картинку и текст, но не цвет.
