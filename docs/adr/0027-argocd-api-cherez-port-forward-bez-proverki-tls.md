# ADR-0027: Argo CD API — через проброс к `argocd-server`, проверка TLS отключена только для 127.0.0.1

## Контекст

Для диффа «желаемое ↔ живое» Sextant должен войти в HTTP API Argo CD и запросить managed-resources. В стандартной установке `argocd-server` отдаёт самоподписанный сертификат. К нему идут через проброс порта ядра (`PortForwarder`), который слушает только 127.0.0.1.

## Решение

HTTP-клиент `ArgoClient` лежит в ядре (`crates/sextant-core/src/argocd.rs`) и ходит на `https://127.0.0.1:<порт>` проброса к сервису `argocd-server`. Проверка сертификата отключена только для `127.0.0.1` проброса; для любого другого адреса клиент не используется. Если у сервера включён `server.insecure`, клиент идёт по HTTP. Проброс принадлежит `AppState.argocd` (`ArgoSessions`, свой `PortForwarder`) и закрывается вместе с кластером. «Open Argo CD UI» открывает в системном браузере `https://localhost:<порт>` (или `http`, если сервер без TLS) через `openInBrowser(forward, scheme)`.

## Почему

- Проверка сертификата включена — отвергнуто: с самоподписанным сертификатом вход не работает в стандартной установке (формулировка спецификации).
- Канал до самого сервера уже защищён: проброс идёт по TLS до API-сервера Kubernetes, а отключение проверки касается только последнего участка на этой машине.
- Принять собственный CA или закрепить сертификат — в материалах не обсуждалось.
- Почему у сессий Argo CD свой `PortForwarder`, а не общий с вкладкой Port Forwarding, в материалах не сказано. Спецификация говорит «тот же `PortForwarder`», имея в виду тип.

## Последствия

- Клиент, ходящий в Argo CD, принципиально не проверяет подлинность сервера. Защита держится на том, что проброс слушает только `127.0.0.1`. Как в коде обеспечено, что исключение не применится к другому адресу, в материалах не описано.
- Браузер при открытии UI на `https://localhost:<порт>` увидит тот же самоподписанный сертификат. Что с этим делает пользователь, в материалах не отмечено; следует из самоподписанности.
- Новый вид долгоживущей сессии регистрируется в `AppState` и закрывается с кластером (ADR-0011, ADR-0012). Токен сессии живёт только в памяти. Виден ли этот проброс в списке Port Forwarding, в материалах не описано.
- Схемы URL (`http`/`https`) теперь поддерживают `urlOf(forward, scheme)` и `openInBrowser(forward, scheme = "http")`; прежний вызов с `http` не меняется.
